**Date:** 2026-05-21
**Auditor:** Claude (Opus 4.7) using [`nav-ia-audit` skill](../.claude/skills/nav-ia-audit/SKILL.md)
**App:** `sandbox/` — vanilla-JS SPA + FastAPI/Supabase backend

---

## Verdict

The app's *features* (engineer profiles, job mapping, dispatch) are not in scope here and are reported by the team as working well. The app's *shell* is the problem. Once a user signs in and picks a project, the entire concept of "I am a person with an identity, working inside a workspace, on one of several jobs" disappears from the screen. There is **no project name shown anywhere**, **no way to switch projects without logging out**, **no user/account menu**, **no breadcrumbs**, **no URL routing**, and **modals are uniformly inaccessible** (zero `role="dialog"`, zero `aria-modal`, zero ESC handling across all six modals).

The information architecture is two flat layers — overlay → app — when it actually has at least four (auth → workspace → project section → resource detail). That mismatch is the largest single source of user disorientation.

## The five headline issues

Each blocks or amplifies many smaller issues. Fix these first.

### H1 — No URL routing (P0, ~2 days)

Navigation is `onclick` → CSS class toggle ([sandbox/frontend/app.js:508-516](../sandbox/frontend/app.js#L508-L516)). The URL never changes after the initial load. Consequences cascade:

- Refresh resets to Map view regardless of where the user was.
- Cannot deep-link to a dispatch run or an engineer profile.
- Browser back/forward do nothing useful.
- Analytics cannot distinguish views.
- 13 separate audit items fail because of this single cause.

**Fix:** Introduce a tiny hash router (~80 LOC). Each section, detail view, and modal becomes URL-addressable. Spec in [`nav-ia-audit/references/routing-deeplinks.md`](../.claude/skills/nav-ia-audit/references/routing-deeplinks.md).

### H2 — No identity surface (P1, ~1 day)

The user's name/email is never rendered in the chrome. The current project is never rendered in the chrome. Team rows even show truncated UUIDs ([sandbox/frontend/app.js:277](../sandbox/frontend/app.js#L277)).

Screenshot evidence: [`docs/nav-audit-screenshots/12-desktop-1440-app-shell-shape.png`](../docs/nav-audit-screenshots/12-desktop-1440-app-shell-shape.png) — the entire top of the app is empty space. No top bar exists.

**Fix:** Add a top bar with a **project chip** (left) and **avatar menu** (right). Specs in [`shell-patterns.md`](../.claude/skills/nav-ia-audit/references/shell-patterns.md), [`workspace-switcher.md`](../.claude/skills/nav-ia-audit/references/workspace-switcher.md), [`account-menu.md`](../.claude/skills/nav-ia-audit/references/account-menu.md).

### H3 — Every modal is inaccessible (P0, ~1 day)

Playwright instrumentation confirmed all six modals fail every basic accessibility check:

```
modals found: 6
[role="dialog"] count: 0
[aria-modal]   count: 0
ESC closes modal: 0 / 6
```

Modals: `create-project-modal`, `project-settings-modal`, `preflight-modal`, `engineer-form-modal`, `job-import-modal`, `ai-review-modal`.

Combined with hardcoded z-indexes (9998, 9999, 10000) and lack of focus trap / scroll lock, this is both an accessibility bug and a fragile stacking system.

**Fix:** Extract a single `openModal({title, content, destructive})` primitive. Refactor existing modals onto it. Spec in [`modals-overlays.md`](../.claude/skills/nav-ia-audit/references/modals-overlays.md).

### H4 — Settings cog with mislabeled scope (P1, ~30m)

The gear icon in the nav rail ([sandbox/frontend/index.html:154](../sandbox/frontend/index.html#L154)) is labeled "Settings" and opens what is, in fact, a *team-management drawer scoped to the current project* — no project name editing, no project deletion, no account preferences. This is the "settings cog as the only escape" anti-pattern compounded by a scope conflation.

Screenshot: [`docs/nav-audit-screenshots/14-modal-01-project-settings-modal.png`](../docs/nav-audit-screenshots/14-modal-01-project-settings-modal.png).

**Fix:** Relabel and re-route:
- Rename to "Team" or merge into a proper "Project settings" surface.
- Move *account*-scoped settings (theme, notifications, password change) under a separate avatar menu (introduced by H2).

### H5 — Sign-out as a standalone rail button (P1, ~1h)

Sign-out lives as a one-click button at the bottom of the nav rail ([sandbox/frontend/index.html:160](../sandbox/frontend/index.html#L160)), with no identity context, no confirmation, no toast. Combined with H2, the rail communicates "you are stuck in this app; the only escape is to log out entirely."

**Fix:** Move sign-out into the avatar menu (bottom, divider above). Add a toast on successful sign-out. Spec in [`account-menu.md`](../.claude/skills/nav-ia-audit/references/account-menu.md).

## The architectural threads (root causes)

Two underlying decisions cascade into most of the 33 failing items. Fixing them once is dramatically cheaper than patching the symptoms.

| Thread | Symptoms | Fix |
|---|---|---|
| **No router** | Refresh resets view, no deep links, broken back button, modals can't be linked, analytics blind, race conditions on project switch | Add hash router (~80 LOC) |
| **No modal primitive** | 6 modals × 8 failed a11y checks = 48 individual bugs; hardcoded z-indexes; inconsistent close affordances | Extract one shared `openModal()` |

Beyond those: there's no shared toast/live region (every error is logged to console), no state store (globals + DOM = source of truth), and no skeleton/empty/error state convention. These are second-order — fix once the foundations land.

## Ordered implementation plan

Each step is independently shippable. Verify per [`pre-ship.md`](../.claude/skills/nav-ia-audit/checklists/pre-ship.md) before moving on.

### Sprint 1 — Foundations (3–4 days)

> Without these, every later step is a workaround.

1. **Add hash router** — ~80 LOC. Wire to existing `switchAppView` so visible behavior is initially unchanged. *Unlocks pillar 3 entirely.*
2. **Extract modal primitive** — single `openModal()` with ARIA, focus trap, scroll lock, ESC, stacked z-index. *Unlocks pillar 6 entirely.*
3. **Add session/state module** — single source of truth for `currentProject` and `currentUser`. Shell components subscribe to changes; views read.
4. **Add `aria-live="polite"` toast region** — used by step 5 and onward.

### Sprint 2 — Shell components (3–4 days)

5. **Top bar component** — empty container, ready to host project chip + avatar.
6. **Project chip** — left of top bar, shows current project name + caret.
7. **Project switcher popover** — opens on chip click; search field, recent + all, "+ New project", "View all projects". Keyboard-driven.
8. **Avatar menu** — right of top bar, shows email; account settings link; sign out at bottom with divider; toast on sign-out.
9. **Promote project list into a `/projects` route.**
10. **Add `/account` route.** Move what's *user-scoped* there.
11. **Remove `Log out` button from the nav rail.** (Replaced by avatar menu.)
12. **Rename `Settings` rail button to `Team`** or fold it into a proper project settings drawer.

### Sprint 3 — Auth + polish (2–3 days)

13. **Forgot password flow** — Supabase `resetPasswordForEmail` + a `/login/reset` route.
14. **401 interceptor in `apiFetch`** — opens re-auth modal preserving form drafts.
15. **Deep-link gating** with `?next=`.
16. **Breadcrumbs** — show when route depth > 1.
17. **Skeletons for project list, engineer list, jobs list, analytics history.**
18. **Empty + error states with CTAs / retry.**
19. **Free wins F1–F10** — bind labels, aria-labels, focus-visible, reduced-motion, autocomplete, landmark elements.

### Sprint 4 — Mobile (2–3 days)

20. **Bottom tab bar** below 768px.
21. **Full-screen modals** below 480px.
22. **Safe-area insets** for iOS.

### Total: ~3 weeks for one engineer

Plus an optional **Sprint 5** for the React migration if you decide to do it — but that should be planned as a separate, scoped initiative (see "Stack note" below).

## Stack note — React migration

Asked separately: viable, not urgent.

- **Docker + GCE**: zero technical blocker. A multi-stage Dockerfile builds the React app and either ships the static `dist/` from the existing FastAPI container or fronts it with a thin Nginx sidecar. The Compose topology and the GCE VM don't care.
- **Real cost**: rewrites ~3,400 LOC of vanilla JS, introduces a build pipeline, picks state management (zustand / TanStack Query / context), picks a UI library (shadcn/ui or Mantine), picks a router (TanStack Router / React Router).
- **Recommendation**: don't bundle this with the navigation work. Do Sprints 1–4 in vanilla JS, validate the new UX with users, then make the React decision with a clearer scope. If you do migrate, the router and modal primitive you build here will be the easiest things to throw away — they're the lightest investments.
